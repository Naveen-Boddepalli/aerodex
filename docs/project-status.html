AeroDex builds a real-time airfare price index for India for MoSPI, on ₹0 recurring spend. The statistical machine is built, tested and reproducible. What it does not have is real fare data — and that is not an engineering problem. Four rounds of research proved that no source in existence gives flight-level fares at controlled booking horizons in a way that is both legally permitted and free. The project's own compliance code refuses to collect from any of them.

So the pipeline runs today end to end on a fixture adapter — synthetic fares that exercise every stage. The publisher deliberately refuses to release a number derived from it. The critical path is now a letter to MoSPI and DGCA asking for access under their statutory authority, running in parallel with continued engineering that is not blocked.

What is built, section by section

Everything below is in the repository, passing tests, and lint-clean under ruff. The claim "built" here means covered by an automated test, not merely written.

Configuration & provenance complete

Three YAML files hold every methodology choice, and none of it lives in Python — config in code is not auditable. Each file is SHA-256 hashed over a canonical serialisation (sorted keys, no whitespace), so reordering keys or reflowing comments does not invent a spurious new vintage, but changing any value always does. Compliance engine complete — 62 tests

The pitch's legal position is enforced as runtime assertions in one file, so violating a rule requires deliberately editing a file called compliance.py. There is no bypass flag, on purpose.

  • No authentication, ever. Authorization, Cookie, X-API-Key and friends are rejected before a request leaves the process.
  • No personal data, ever. A field-name denylist (names, email, PNR, passport, payment, loyalty numbers) blocks it at the record level.
  • 20-second floor between requests to the same host, enforced by a thread-safe rate limiter rather than by convention.
  • A custom RFC 9309 robots.txt parser. Python's urllib.robotparser was found to have four defects, each of which silently granted access a site had refused — including discarding an entire ruleset. That discovery is written up in docs/spikes/robots-parser-defects.md and drove the replacement.
  • Unreachable robots.txt means disallowed. So do 401, 403 and 429 — a robots file behind auth is a signal about automation, not an absence of one.
  • A User-Agent that names the project and links to the repo.

Acquisition framework framework done, no real source

The adapter contract is deliberately narrow: search() → parse() → emit(), one file per source, so a failing source is isolated. It encodes the three-tier ladder — documented public JSON, then internal XHR endpoint, then full Playwright render only as a last resort. On 2 OCPU that ordering is the difference between a 60-route panel and a 10-route one.

The only adapter that exists is fixture.py, which makes no network calls and marks itself is_synthetic = True. Its flight roster is seeded on route and horizon (so the same flight numbers recur daily, as real schedules do) while only the fare moves — which is exactly what matched-model comparison needs to be exercised honestly.

Index engine core complete — 11 golden + 12 elementary tests

compute_index(panel, config) → DataFrame is a pure function: no clock, no database, no network. That single constraint is what makes reproducibility achievable, and a test literally parses the module's source to assert it never acquires one of those imports — because that failure would only surface as a published number quietly moving months later.

  • Jevons elementary index, computed in log space so large panels do not underflow. Chosen over Carli (upward bias) and Dutot (not unit-invariant).
  • Lowe/Laspeyres aggregation on fixed DGCA traffic weights, with renormalisation over the strata that actually reported.
  • Imputation by group-mean movement, with the imputed share of weight published on every index point and a hard ceiling flag at 5%.
  • Coverage ratio and matched-quote counts emitted per period.
  • Output hashing rounded to six decimals — float noise below published precision is not a reproducibility failure, but anything visible in a published number is.

Reproducibility guarantee (M6) proven

A frozen input panel and a frozen expected output are checked in. Eleven golden tests assert bit-identical re-runs, that row order cannot change the result, that two runs in one process do not differ, that weights actually reach the engine, and that a deliberate coverage hole surfaces as an M5 flag rather than vanishing. Publication guard refusal logic done, delivery missing

The artifact builder assembles index_latest.json, index_full.csv, a dated release and methodology.json — and refuses two things outright: a panel whose only source is synthetic, and any period that breached the imputation ceiling. Both raise PublicationRefused. What is missing is everything downstream: the R2 upload, the dashboard and the API.

Automation 3 of 4 workflows

  • ci.yml — spins up TimescaleDB, applies the schema, lints, runs the suite, then runs the M6 verify as a separate named step.
  • reproducibility.yml — nightly at 02:00 IST, re-verifies the frozen hashes.
  • keepalive.yml — pings every 20 days to defeat GitHub's 60-day disable of scheduled workflows on inactive repos.
  • backup-collector.yml — missing planned as the redundant 6-hourly collector.
  • systemd units — a templated service and timer per slot, with jitter, plus a README explaining that OnCalendar cannot read a clock time from the instance name so each slot needs a drop-in.

Research output substantial deliverable in its own right

Over 3,200 lines of primary-source research across docs/spikes/ and docs/research/s3/: forty-plus candidate sources assessed on nine independent axes, terms of use read clause by clause, 38 claims individually registered with evidence and confidence, and one genuine empirical experiment on 14 archived tariff sheets. This is presentable material — it is the reason the project can state its compliance position as a finding rather than a promise.

04

The blocker, and why it is not an engineering problem

Spike S3 — final verdict

B — Proceed with the permission path. The methodology is sound. The blocker is data access, and it is external to the project. No source provides flight-level offered fares at controlled booking horizons, permitted, at ₹0. Zero candidates survived out of forty-plus, across four research passes.

The pattern that decides it

Read two columns of the source matrix together and the structure appears immediately: every source with a booking horizon fails "automation permitted", and every source that permits automation has no horizon. That is not coincidence. It is look-to-book economics — every distribution channel meters search and recovers the cost from bookings, and AeroDex books nothing. Duffel writes it into contract (zero orders are counted as one order); Travelpayouts states it in plain words. This is why further source-searching has negative expected value.

The experiment that closed the last escape route

Research pass 2 found something genuinely new: Rule 135 of the Aircraft Rules 1937, plus a DGCA direction, compels every scheduled Indian carrier to publish route-wise tariff sheets. Free, structured, archived. Pass 2 proposed building the index on them. Pass 3 tested that proposal against 14 archived IndiGo sheets and killed it on three independent grounds:

  • A fare level is a band, not a price. Median Maximum/Minimum ratio 1.25×–1.52×, p90 up to 2.82×, only 0.3–2.5% of cells identical. Any index must pick an arbitrary point inside the band — and the band is narrowing over time, so a midpoint index would read band compression as deflation.
  • The levels are not stable strata. Median same-level month-over-month movement runs −21.3% to +10.0%; 12–53% of matched cells move more than ±25%; the best-matching ladder offset is non-zero in 5 of 11 consecutive pairs.
  • The route panel churns. 4,110 → 1,919 routes in a single step: 46.6% survival. The schema changed three times in eighteen months.

Pass 3 also ran the compliance check pass 2 never ran, separating robots.txt from terms of use — and four of the five "clean" sources failed the project's own gate.

Why this is the strongest part of the submission

The research reversed itself twice and recorded both reversals rather than rewriting history. It distinguishes "not found" from "does not exist", marks claims resting on secondary sources as primary source not verified, and keeps robots status and Terms status as separate columns because conflating them changed four verdicts. Judges see a team that tested its own hypothesis and let the data win.

Two findings that reframe the whole project

  • MoSPI already does exactly what AeroDex proposes. The CPI 2024 FAQ (Q27) records that airfares are collected through well-known online platforms. The difference between MoSPI's lawful collection and AeroDex's unlawful collection is statutory authority under the Collection of Statistics Act 2008 — not technique.
  • The methodology is independently corroborated. MoSPI's own CPI 2024 series uses Jevons for elementary indices and a Laspeyres-family aggregation above — matching AeroDex's two most important choices. The IMF Technical Assistance mission to MoSPI separately recommended multiple advance-purchase horizons and naming the airline as a price-determining characteristic; the 7-horizon carrier-attributed panel already does both.

Four passes of adversarial research produced 14 keep, 0 change against the methodology config. That is a real result, not an absence of one.

Time-sensitive

The methodology sets base.period: "2026-09" — the index's reference period, where the value is 100 by definition. That period starts in about a week and no real observation exists. If access does not land before then, the base period passes with no data and the index has nothing to chain from. The fix is a one-line config change, but somebody has to decide and it should not be discovered late.

07

Concepts and jargon

Read this before your first code review. Most of the vocabulary comes from official price statistics, not from software.

stratum
One (route, booking horizon) cell — for example DEL–BOM at 7 days out. 60 routes × 7 horizons = 420 strata. The index is computed per stratum, then aggregated.
booking horizon
Days between the collection date and the departure date. Airfares move enormously with horizon, so comparing a 1-day fare to a 60-day fare would measure booking behaviour rather than price change.
slot
A fixed daily collection window: 07:00, 13:00, 20:00 IST, each with ±15 minutes tolerance. Late collection degrades gracefully instead of voiding the stratum.
matched model
Only itineraries present in both periods contribute to a price relative. That is what stops a new expensive flight appearing in the panel from reading as inflation — and it is why quality adjustment is needed separately.
Jevons
The elementary index: the geometric mean of price relatives. Beat Carli (known upward bias) and Dutot (not unit-invariant, wrong for heterogeneous items). MoSPI uses Jevons too.
Lowe / Laspeyres
The aggregation above strata, using fixed weights from a past period. Fisher and Törnqvist need current-period quantities the project does not have.
hedonic
Quality adjustment by regression: predict log fare from stops, timing, carrier type, duration, refundability and baggage, so a change in what is being sold is not read as a change in price.
imputation
Filling a stratum that did not report, using the mean movement of its route group. The share of index weight that was imputed is published on every index point and capped at 5%.
coverage ratio
The fraction of strata that actually reported. Published on the dashboard, not just internally — disclosing it is what distinguishes official statistics from a scraped chart.
chaining
Linking successive monthly index levels so the series survives panel churn without a discontinuity.
weights vintage
A string identifying exactly which weight set produced a number, e.g. dgca-2025-city-pairs-r2. One vintage string must never describe two different weight sets, so the mapping revision is bumped whenever the city-to-IATA table changes.
config hash
SHA-256 over the canonical serialisation of the methodology. Stamped on every index point, so any published number can be traced to the exact rules that produced it.
pure function
The engine reads no clock, no database and no network. Enforced by a test that inspects the module's own source. This is what makes reproducibility a property rather than a claim.
tier 1 / 2 / 3
The acquisition ladder: documented public JSON, then internal XHR endpoint with correct headers, then full browser render. Tier 3 costs 10–50× more CPU, and on 2 OCPU that decides the panel size.
quarantine
A quote that fails plausibility is held, not deleted. The quarantine queue is evidence about a source's health.
look-to-book
The economics that block every distribution channel: search costs money, and the cost is recovered from bookings. A project that books nothing is pure cost, so contracts forbid it. This is the structural reason S3 failed.
Rule 135
Aircraft Rules 1937 — requires carriers to establish and publish tariffs, on a website or in two daily newspapers. The source of the tariff sheets that were investigated and rejected.
ODbL
The Open Database Licence covering the DGCA traffic mirror the route weights come from. It requires attribution, which the README carries.

Rule for golden tests

If a golden test fails, that is the system working. Never "fix" it by re-freezing. If the change was intentional, re-freeze deliberately and say so in the commit message — a moved hash is a moved published number.

The pattern worth noticing

Almost every finding is the same shape: configuration or prose promises a behaviour the code does not yet have. This project's own best idea — putting rules in compliance.py so violating one requires editing a file named after the rule — is the cure. Where to start

Your first hour

  • Read docs/research/s3/S3_EXECUTIVE_SUMMARY.md — two pages, and it explains why the project looks the way it does.
  • Run uv sync --extra dev then uv run pytest -q. Green in under a second.
  • Run aerodex panel and aerodex verify. You have now seen the two things the project guarantees.
  • Open aerodex/index/engine.py and tests/golden/test_golden.py side by side. Everything else in the codebase serves those two files.
  • Skim plan.md §5. Any "why not X?" you have is probably answered there with the constraint that killed X.

If you own the project

Send NA-1 and NA-2 today. The letters are drafted in NEXT_ACTIONS.md and need only an addressee check and a signature; the response window is 2–6 weeks and the SIH timeline does not have slack for a late start. Then decide the base period question (A-14) before September arrives.

If you write code

Take U-1 (hedonic), U-2 (eSankhyiki benchmark) and U-3 (coverage metric) first. All three are unblocked, all three close a gap between what the project claims and what it does, and all three are visible in the submission. Then U-7, the dashboard — it is the artefact judges will actually open, and it is the one place where publishing M3 and M5 on the public page does real persuasive work in five seconds of attention.

Three rules the team has already agreed

  • Do not write acquisition adapters. Explicitly blocked in the decision record until written permission naming a specific source arrives. A live adapter would create the exact compliance exposure the whole design exists to avoid.
  • Do not treat public accessibility as permission. This error was made twice in the research and caught twice. It is why robots status and terms status are separate columns.
  • Do not re-freeze a failing golden test to make it pass. If the number moved, find out why.
How to pitch this

The instinct will be to hide the missing fare data. Do the opposite. The strongest version of this submission is: we set out to scrape fares, discovered systematically that no one legally can at zero cost, proved it with an experiment that killed our own preferred workaround, built the complete statistical machine anyway to the standard the sponsoring ministry uses — and identified that the ministry itself holds the authority that would unlock it. A team that can show its own falsified hypotheses is more credible than one showing a chart.
